# 部署前准备清单

> 适用版本：审计修复版（2026-10-15，基于 P1.6 + 安全修复集）。本文档面向首次部署到新服务器的操作者。

## 一、部署物形态

项目为纯静态站点，部署只需 `dist/` 目录内的 8 个文件，无需 Node、无需构建服务器：

```
dist/
  index.html        页面（内联 CSS+JS，数据经 <script src> 加载）
  data/courses.js   课程数据脚本（205 门）
  data/paths.js     路径数据脚本（5 条）
  _headers          安全响应头（CSP 等，见第三节平台说明）
  _redirects        SPA 回退规则（hash 路由下冗余，可不上传）
  robots.txt
  sitemap.xml
  .nojekyll
```

`release/humanities-courses-p1/` 是完整交付包（含源码、工具、schema、文档），用于归档或复刻，不是上传物。

## 二、部署步骤

1. **确定正式域名**（https）。部署前必须选定，否则站点继续引用 CloudBase 测试域名。
2. **带域名重新构建**（在项目根目录，Node ≥22）：
   ```bash
   SITE_ORIGIN=https://你的域名/ node tools/build-site.js
   ```
   该环境变量会联动重写 canonical、og:url、robots.txt 的 Sitemap 行与 sitemap.xml 全部 loc。省略此变量则沿用 index.html 内的 canonical（当前为测试域名）。值不含 scheme 或格式非法时构建直接报错。
3. **上传 `dist/` 全部内容**到服务器站点根目录（保持目录结构，`data/` 子目录必须一起上传）。不要把开发目录（含 tools/、docs/、validation/）上传到站点根。
4. **验证部署**（本机需有 Chrome）：
   ```bash
   node tools/public-smoke.mjs https://你的域名/
   ```
   该命令以真实浏览器访问公网地址，验证页面加载、课程渲染与运行错误，结果写入 `validation/`。
5. **确认安全头生效**：访问首页，浏览器开发者工具 → 网络 → index.html → 响应头，应含 `content-security-policy` 且 script-src 为 `'self'` 加两个 `sha256-` 值（无 unsafe-inline）。若服务器不解析 `_headers`，见第三节。

## 三、平台差异须知

- `_headers`（Netlify/Cloudflare Pages 约定）：若新平台解析，CSP 等安全头经响应头下发；**若不解析，index.html 内的 meta CSP 仍然生效**（script-src 纯 hash 已在 meta 内），此时建议在服务器侧手工配置同等安全头，并在文档中记录唯一配置源，避免两处漂移。
- `_redirects`：本站深链全部为 hash 片段（`#course=` / `#f=`），服务端不需要回退规则，任何平台下该文件都是冗余，可删。
- `.nojekyll`：仅 GitHub Pages 需要，其他平台无害。
- 必须启用 **https**：CSP、剪贴板 API（分享/复制按钮）均要求安全上下文。

## 四、部署后检查单

- [ ] 首页加载 205 门课程，无白屏
- [ ] 地址栏深链可分享还原（`#f=plat=B站&acc=free`）
- [ ] 学习规划面板可打开（笔记/打卡/热力图，数据仅存本机 localStorage）
- [ ] 分享按钮复制出的链接不含任何查询参数与片段
- [ ] 响应头或 meta CSP 生效（script-src 无 unsafe-inline）
- [ ] sitemap.xml 可访问且域名正确
- [ ] 控制台无运行时报错

## 五、持续维护

- **数据更新流程**：只编辑 `data/courses.json` 与 `data/paths.json` → `node tools/build-data-script.js` → `node tools/build-site.js` → 上传 dist/。改完后务必先跑 `npm test`（7 条门禁，零网络依赖）。
- **CI**：仓库推送到 GitHub 后，`.github/workflows/ci.yml` 会在 push/PR 时自动运行 `npm test`；links.yml 每周巡检死链。未推送则 CI 不生效。
- **版本控制**：修复副本已 git init 并完成首次提交，后续改动先提交再构建。
- **已知残余**：11 条失效外链（9 条 B 站 legacy av 号 + 2 条 BV 号）属已阻断课程，不影响访问。（浏览器回归两类偶发假失败——CDP 超时、过渡态采样——已由接收方于 2026-10-25 修复：轮询等待 + 超时重试，build-release 首跑通过。）

## 六、安全事项

- 发布包内无任何凭据（已专项扫描验证）；部署令牌只放平台或 CI Secret，勿入代码与压缩包。
- 联网巡检工具（audit-links --network）已内置 scheme 与内网地址黑名单；其重定向跟随策略的残余风险已知会记录在案。
- EdgeOne 平台已弃用（2026-11-02 委托人决议，改用 GitHub Pages 部署）：旧部署 Token 作废，本地本就无任何凭据文件（专项扫描+发布禁止项双重把关）；如该平台账号仍在使用，控制台侧的作废操作由账号持有人完成。
