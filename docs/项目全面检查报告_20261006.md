## 四、新发现的真实缺陷（3 项，均有机械证据）

### 4.1 【P0 工程治理】`audit:round2` 门禁已失效，但 README 仍要求发布前运行

**现象**：18 项检查中 5 项失败。

| 失败项 | 证据 | 根因 |
|---|---|---|
| 课程与入口口径 | 实际 130 / 108 / 22 | `tools/second-round-audit.js:28` 硬编码 `courses.length===79 && linked===57` —— 2026-07-31 的快照基线，数据长到 130 后未更新 |
| 稳定身份 | 实际 130 唯一 | 同上，`:29` 硬编码 `size===79` |
| 路径引用闭合 | 17 条引用非 `core` 门课程 | **真问题**，见 §4.2 |
| 联网报告数据版本 | sha256 不匹配 | `validation/link-network-report.json` 停留在 2026-07-31（79 门版），当前 courses.json 已是 130 门 |
| 前台无治理术语 | 命中 1 行 | **误报**：`index.html` 的 `GOV_MARKERS` 常量数组里存着「入口已核/来源已核/内容错配」用于**剥离**这些词；真实可见性由 `browser-smoke` 的 `visibleAuditLabels === 0` 断言保障（现为 0） |

**影响**：`README.md:17` 把 `audit:round2` 列为发布前必跑项，实际执行必然失败 → 流程文档与工具脱节；真正的联网门禁（`audit:network`）因缺 sha 匹配的产物而无法通过该项。

**建议**（二选一，我推荐 A）
- **A（推荐）**：把 `second-round-audit.js` 改造为**基线外置**——从 `data/courses.json` 动态推导 `总数/可跳转/阻断`，用 `editorial_status` 判定「核心候选」，治理术语检查改为「仅扫可见文本节点」而非全文件 grep；随后 `npm run audit:network && npm run audit:round2` 恢复可用并纳入 `npm test`。
- **B**：把该脚本降级为历史快照审计，改名 `audit:round2-snapshot` 并在 README 标注「仅适用于 2026-07-31 基线」。

### 4.2 【P1 数据一致性】核心候选双轨标识，导致 17 条路径引用「看起来违规」

**证据**（脚本核查 `data/paths.json` × `data/courses.json`）：

| 路径 | 引用数 | 问题 |
|---|---|---|
| 神话学 / 文学理论 / 古典诗词 | 26 | 合规 |
| **书法入门：从审美到临池** | 8 | 全部指向 `core=false` 的课程（hc-080~087） |
| **国画入门：从读画到笔墨** | 9 | 全部指向 `core=false` 的课程（hc-088~109） |

**根因**：数据里有两个并行的「核心」概念——布尔字段 `core`（仅 20 门为 true）与 `editorial_status = core_candidate`（71 门，国画/书法 51 门全部属于此类）。两条草案路径引用的是**按状态口径**的候选课，而门禁按**布尔口径**判定 → 必然失败。

**这需要你拍板**（已登记为 OPEN-1）：
- 方案甲：把书法/国画 17 门（或全部 51 门）`core` 置 true → 核心候选变为 71 门，与状态口径一致，但「首轮复核」范围扩大
- 方案乙：门禁改用 `editorial_status` 判定 → 数据不动，语义更准（推荐，改动 3 行）

### 4.3 【P1 交付物】`vibex-handoff` 交付包违反 P0-1 且结构重复

**证据**：
- `vibex-handoff/index.html` 含 ★(U+2605)×12、☆(U+2606)×6 —— 这是 P0-1 明令禁止的「符号字形充当难度图标」旧实现（主线已于 `9d1576b` 改为三档电平条 SVG）
