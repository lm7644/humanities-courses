## 0. 筛选原则与硬约束

### 三条筛选标准（本次执行口径）

1. **工作量门槛**：只纳入中等及以上（≥1 人日量级）、边界明确的模块。3 行修复级的技术债（density 持久化、死代码删除、监听器合并）一律忽略，留给本地顺手清理。
2. **独立性优先**：依赖少、可独立验证、与主流程耦合度低者优先。
3. **风险标注**：可拆分但接缝处风险高的，仍列出但明确标注原因与建议切法。

### 决定可行性的三条硬约束

**约束一：VibeX 沙箱没有 Node 运行环境。**
交接包 `AGENTS.md` 已明确：「Node 22 仅用于构建/校验脚本（本交接包不含，见原项目 `tools/`）」。交接包之所以做成单文件内联版，正是因为沙箱跑不了构建链。

> **推论：任何 Node 脚本类任务，VibeX 既无法开发也无法验证**——它写出来的脚本在自己环境里跑不起来，只能空转。

**约束二：附件白名单只有 html / md / json，且 ≤5 个。**
禁传 `.js`/`.css`/`.png`。这意味着：
- 无法把 `tools/audit-links.js` 这类现有实现交给 VibeX 作参考（只能以代码块形式嵌进 md 文档）；
- 无法交付任何构建产物（sitemap、robots、分离的 JS 模块）。

**约束三：回灌接缝。**
VibeX 改的是单文件内联版，原项目是「JSON 源 → `build:data` → `data/*.js` 外链」结构。
> 凡改动 `index.html` 的**逻辑段**（非数据段），回灌时必须人工 diff 合并；改动越靠近 `render()` / 状态机 / 深链编解码，合并冲突概率越高。

### 由三条约束推出的判断公式

> **能在单个 `index.html` 内用前端代码完成、浏览器打开即可验证、改动能干净回灌 → 适合 VibeX。**
> **需要 Node / npm / 出网 / 构建产物 / 改 `data/*.json` 源 → 一律不适合。**

### 当前已实现（不重复规划）

深链（`#course=` / `#f=`，含 `t=` 技法键）、分类/平台/难度/技法筛选、收藏 v2 + 导入导出、对比、路径进度、hm-study 基础标记、P0-1 SVG 图标体系、国画/书法分类与技法筛选。

### 当前未实现（本次规划的原料）

SEO 三件套（JSON-LD / OG / canonical / sitemap / noscript 命中数为 0）、拼音与模糊搜索、`link_checked_at` 卡片可见化、源码拆分、`bili-series-audit.js`、死链巡检 CI、`alternative_views` 同课关联、分类多选、hm-study 增强。

## 1. 建议交给 VibeX 的模块（5 个，按优先级排序）

### P1 · 卡片核验信息可见化与失效上报 ★ 首选派发

| 项 | 内容 |
|---|---|
| **功能范围** | 课程卡展示 `link_checked_at`（核验日期）；被阻断课程（`unavailable`/`needs_review`）以小字显示具体失效原因；新增「报告失效」入口（无后端，复制预填文本或 `mailto:` 到策展邮箱）；可选加一条自救提示（如何找替代入口）。 |
| **涉及文件** | `index.html` 的 `cardHTML()` 段；只读 `courses.json` 已有字段（`link_checked_at`、`schedule`、`known_limits`），**不改数据结构** |
| **前置依赖** | 无 |
| **验收标准** | ① 全部卡片可见核验日期；② 阻断课程显示原因小字，且**不得出现治理黑话**（沿用现有 `visibleAuditLabels === 0` 断言，即页面不得出现「入口已核」「来源已核」「内容错配」字样）；③ 报告入口点击后有明确反馈；④ `browser-smoke.mjs` 中 `.go.disabled` 数量与数据一致；⑤ 桌面与移动端均无横向溢出（`scrollWidth === clientWidth`） |
| **适合理由** | 只读数据、单边 UI 追加、不碰状态机与深链。改动集中在 `cardHTML()` 一个函数内，回灌时 diff 面最小。是验证 VibeX 协作流程是否顺滑的最佳试水模块。 |

### P2 · 站点元信息与结构化数据（SEO 前半段）

| 项 | 内容 |
|---|---|
| **功能范围** | 在 `index.html` 的 `<head>` 内联写入：JSON-LD（`ItemList` + `Course`，由课程数据派生）、Open Graph / Twitter Card 元信息、`canonical` 链接、页面描述。全部内联在单文件内，不引外链、不发运行时请求。 |
| **涉及文件** | `index.html` 的 `<head>` 段 + 启动时注入 JSON-LD 的一小段脚本 |
| **前置依赖** | 无（数据在 `window.HUMANITIES_COURSES` 已就绪） |
| **验收标准** | ① Rich Results Test 识别 `ItemList`+`Course` 无错误（VibeX 侧可用浏览器查看页面源码自查，最终由本地用线上工具复核）；② `file://` 与 `http://` 下元信息均存在；③ **不违反 CSP**——`connect-src 'none'`，不得为取元信息发起任何网络请求；④ 不引入外部 CDN 资源 |
| **适合理由** | 纯 HTML head 改动 + 一段派生脚本，浏览器打开即可验证，不触碰渲染主流程。 |
| **接缝提醒** | OG 卡片图需注意：项目封面是程序化 SVG，社交平台普遍不解析 SVG。建议本期**先不设 `og:image`**，或用轻量 data-URI PNG。**不要为此引入图片生成依赖**。sitemap / robots / noscript 属构建期产物，见 X4。 |

### P3 · 同课多入口关联（alternative_views 落地）

| 项 | 内容 |
|---|---|
| **功能范围** | 检测并关联同课的不同平台入口（已知三组重复），写入 `alternative_views` 字段；卡片显示「另有 N 个入口」角标并可查看；新增查重告警。 |
| **涉及文件** | `data/courses.json`（回填字段）、`index.html` 卡片渲染与角标；检测逻辑可独立成脚本（但 VibeX 侧只能产出 md 形式的检测报告，见下） |
| **前置依赖** | 需先确认「同课」判定口径（同名 + 同讲师，还是同内容不同平台）。**建议第一步只出检测报告，确认后再回填数据** |
| **验收标准** | ① 三组已知同课双向关联且卡片角标正确；② `alternative_views` 双向一致（A 里有 B，B 里必有 A）；③ 新增重复 URL 时现有「重复 URL」门禁报 ERROR；④ `browser-smoke` 通过 |
| **适合理由** | UI 部分只是卡片内追加角标，耦合度可控。 |
| **接缝提醒** | 数据回填在 VibeX 侧改的是 `data.json`，回灌原项目时要同步进 `data/courses.json` 并重跑 `build:data`。**门禁代码（`validate-project.js`）的改动请 VibeX 只以代码片段形式给建议，由本地合入**，避免两边同时改同一文件冲突。 |

### P4 · 分类筛选多选化

| 项 | 内容 |
|---|---|
| **功能范围** | `category` 从单选改为多选（chip 可叠加）；顶部显示当前筛选条件摘要条；提供「一键重置」回到初始状态。 |
| **涉及文件** | `index.html` 的 `state` 结构、`buildFilters()`、`render()` 过滤逻辑、`encodeState`/`decodeState` 深链编解码 |
| **前置依赖** | 无 |
| **验收标准** | ① 多选组合筛选结果与数据一致；② 深链可完整还原多选状态（含与 `t=`/`m=` 共存）；③ 重置后回到初始筛选；④ `browser-smoke` 中「筛选按钮不重复」类断言仍成立 |
| **⚠️ 接缝风险（高）** | `state.category` 由字符串变为数组，会**同时**牵动四处：① `render()` 过滤分支；② 深链 `encodeState`/`decodeState` 的 `#f=` 格式；③ miniNav 双向同步；④ `browser-smoke.mjs` 中与分类相关的断言。四处分散在文件各处，VibeX 改完回灌时**几乎必然与本地改动冲突**。 |
| **建议切法** | 若仍要交给 VibeX，**只让它交付 UI 交互原型**（多选 chip 的视觉与交互 + 摘要条 + 重置按钮），**深链编解码与 `state` 结构变更留本地**；或整块留本地，在完整门禁下改。 |

### P5 · 学习规划增强（hm-study 二期）

| 项 | 内容 |
|---|---|
| **功能范围** | 课程级笔记、学习状态细分（想学/在学/学完）、学习提醒、`.ics` 日历导出、学习热力图、与 `series.total_pages` 联动显示「学到第 N 讲 / 共 M 讲」进度百分比。 |
| **涉及文件** | `index.html` 大段新增；`localStorage` 中 `hm-study` 由 v1 升 v2；卡片与路径两个渲染区 |
| **前置依赖** | 现有 `hm-study` v1（仅「已学」集合）已在用，需做数据迁移 |
| **验收标准** | ① 老 v1 数据平滑迁移不丢失；② 刷新后笔记与状态持久；③ `.ics` 可被系统日历导入；④ 热力图在桌面/移动端均不溢出；⑤ `browser-smoke` 通过 |
| **⚠️ 接缝风险（高）** | 两处硬接缝：① **localStorage schema 升级**——存量用户数据迁移，VibeX 沙箱里没有老数据可供回归，测不出真实迁移路径（项目已有 `migrateFavoriteRefs` 先例，说明迁移逻辑必须谨慎）；② 热力图与提醒是**新增 UI 区块**，会改动卡片与路径的既有布局，而当前布局刚在 P1.5 定稿并通过移动端溢出断言。 |
| **建议切法** | 拆为两块：**「`.ics` 导出 + 热力图」** 可独立交给 VibeX（纯新增、不碰既有数据结构、可独立验证）；**「笔记 + 状态机 + v1→v2 迁移」** 留本地，必须在有真实老数据的环境下做。 |

## 4. 交付与回灌建议

1. **一次只派一个模块**。VibeX 返回的 `index.html` 是全量文件，多模块并行会导致回灌时互相覆盖。
2. **回灌前先 diff**。用本地 `index.html` 与 VibeX 返回版逐段比对，**只合并目标模块的改动，不要整文件覆盖**——内联数据段尤其危险（本地是外链结构，VibeX 版是内联结构）。
3. **回灌后必须跑完整门禁**：`check:data` → `check:core` → `validate` → `audit:plan` → `audit:offline` → `browser-smoke` → `build:site` → `replica-smoke`，八项全绿才算收。
4. **交接包需重新生成**。每次原项目变动后，用「从修复后的原项目重建单文件」的方式重新生成 `vibex-handoff/index.html`，**不要手工同步内联数据**（此前用正则替换已造成过一次 JS 语法破损）。

## 5. 总结

本次共评估 12 个候选：**纳入 5 个、排除 7 个**。

- **建议交给 VibeX（5 个，按序）**：卡片核验信息可见化 ★ → 站点元信息/JSON-LD → 同课多入口关联 → 分类多选（高风险，建议只交 UI 原型）→ 学习规划增强（高风险，建议只拆 `.ics` 与热力图）。
- **不建议交给 VibeX（7 个）**：B 站系列审核工具（**本次修正**：Node 脚本，沙箱无 Node）→ 源码拆分 → 死链巡检 CI → sitemap/noscript → 拼音注入 → 搜索交互增强 → 自定义学习计划。

**本次修正说明**：上一版把「B 站系列审核工具」列为首选，是只看到它「依赖少、边界清晰、回灌零冲突」，却忽略了最前置的一条——**它是 Node 脚本，而 VibeX 沙箱根本没有 Node**。依赖少不等于能执行。已按「约束一」重新归类，首选改为真正可在单文件内完成并验证的「卡片核验信息可见化」。

**未纳入的三类原因**：

1. **琐碎**：density 持久化、IntersectionObserver 死代码删除、`searchInput` 双监听器合并——均属 3 行至半小时级修复，按标准 1 忽略，留本地顺手清理（其中监听器合并是 X6 的前置，建议优先做掉）。
2. **非开发任务**：Token 吊销、git 化与许可证、教师学术审定、`access_mode` 补数、真机与试用矩阵——需平台权限、专业判断或真实环境。
3. **触发条件未满足**：每课一页预渲染（阈值 >200 门，当前 130 门）。

**最值得优先派发**：P1（卡片核验信息可见化）——纯只读展示、改动集中在单个函数内、浏览器打开即可验证，是用最低成本检验 VibeX 协作链路的试水模块。跑通一轮、确认回灌流程顺滑后，再派发 P2、P3。
